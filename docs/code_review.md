## A. Live code on `origin/master` (prod-exposed)

### F1 — Third-party crisis match wipes co-occurring direct SI flags · **CRITICAL**

- **Where:** `src/sage_poc/nodes/safety_check.py:116-118` (verified: `if third_party_flags: new_crisis_flags = []`, unconditional)
- **Defect:** When any `third_party_crisis` rule (SK-EN-004) fires, the code empties the entire crisis-flag list for the turn — a full-message wipe, not the span-scoped suppression the rules engine itself uses (`rules/engine.py::_apply_suppressions`, which documents "missing position data is not grounds for hiding a crisis signal").
- **Verified downstream:** `_this_turn_is_safe = len(new_crisis_flags) == 0` (`safety_check.py:223`) and `graph.py:170` routes `"safe" if state["is_safe"] else "crisis"`; `graph.py:160` uses the same value for monitoring re-escalation (`not state["is_safe"] or s7_result == "NEW_CRISIS"`).
- **Failure scenario:** "I've been thinking about ending my life too — my sister is suicidal and I'm scared for both of us." Both a direct SI rule and SK-EN-004 match; the wipe empties the list, `is_safe` becomes True, and the turn routes to `intent_route` instead of `crisis_response`. The user's own SI never reaches the deterministic crisis surface; only a discretionary prompt-layer hint remains. The same wiped value can suppress re-escalation during post-crisis monitoring.
- **Spec basis (owner-ratified):** this is a Cardinal Rule 4 violation, and the correct behavior is already specified — v7 §5.1 mandates OR-fusion (any crisis signal → crisis protocol), and Intelligence Evaluation T-10 defines third-party semantics precisely: third-party report *alone* → no crisis protocol for the current user, but provide resources; it says nothing about suppressing co-occurring first-person SI. The span-scoped fix is therefore the only reading consistent with the ratified spec, not a design choice.
- **Action:** Make the third-party override span-scoped, mirroring `_apply_suppressions`: drop only flags whose matched span overlaps the third-party match. Add the compound regression fixture in **both directions** (direct SI + third-party → crisis fires; pure third-party → no crisis, resources offered) — this also closes the T-10 test gap the Intelligence Evaluation flagged as untested. Treat as Lane-1 priority.

### F2 — Curly-apostrophe input bypasses three Node-4 safety-veto lexicons · **HIGH**

- **Where:** `src/sage_poc/nodes/ocd_compulsion.py:32,41`, `nodes/harm_intrusive.py:41,50`, `nodes/ipv_preempt.py:32,38`
- **Defect (verified):** All three vetoes normalize with bare `.lower()`, while `rules/normalize.py` explicitly maps U+2019 → `'` (line 23, commented "iOS/Android apostrophe") plus NFKC for the rules engine. The lexicons contain ASCII-apostrophe patterns (15 in `ipv_preempt_expansion.json`, 3 in `ocd_compulsion_patterns.json`; zero curly variants), and `state.get("message_en")` reaches the matchers unnormalized — `normalize_text` has no call site outside `rules/` (verified by grep).
- **Failure scenario:** A mobile user types "I can't stop checking the stove…" with a smart apostrophe. `is_ocd_compulsion` returns False; the turn is not vetoed and can route to a skill the module's own docstring identifies as iatrogenic for OCD content. Same mechanism for harm-intrusive and the IPV §6a expansion phrases. Silent, input-device-dependent disarming of safety surfaces — and it undermines the V1 iatrogenic-OCD hotfix these vetoes exist to hold. No test in the repo exercises curly-quote input against these modules.
- **Action (owner-ratified into P0, bundled with F8 as one normalization change):** Route input through `sage_poc.rules.normalize.normalize_text` in all three modules plus the §3a detector. Add curly-quote fixtures. A "deterministic" safety layer that behaves differently by keyboard is not deterministic in the Cardinal Rule 4 sense, and the spec already mandates input normalization (S5), so this restores the spec rather than deviating from it. No clinical re-sign-off needed, but **record the reading in the audit trail** — these lexicons are clinician-owned artifacts.
- **Two-branch split (owner disposition, F2 implementation pass):** "F2+F8 as one change" is one *reading* (normalization, not lexicon change), mechanically split across two branches: the three vetoes live on master and are fixed on `fix/f2-veto-normalization`; `low_mood_detect.py` exists only on `feat/low-mood-3a-impl`, so **F8 is a recorded rider** — the identical seam (`_NORMALIZED = tuple(normalize_text(p) …)`; `normalized = normalize_text(message_en or "")`) applied when the §3a branch rebases onto post-F2 master during the P3 rebuild. Ready-to-drop F8 fixture: `assert is_low_mood_disclosure("I don’t feel like doing anything") is True` (U+2019; plus an ASCII pin and a curly-quote negative, mirroring `tests/test_veto_input_normalization.py`).
- **Tip drift note (post-review, PR #450):** on current master both vetoes are variadic and `is_ocd_compulsion` reads raw input via `state.safety_text()` (ADR 2026-07-16 language contract), so the OCD Arabic patterns are live — the review's `message_en`-only description held at the review snapshot. The normalization defect (bare `.lower()`) was unchanged by #450 and is what F2 fixes. `harm_intrusive_patterns.json` carries **no** apostrophe patterns, so its non-ASCII fixture uses ZWSP (`strip_invisible`), the same input-artifact class.

### F3 — Blocking synchronous BGE-M3 inference on the event loop in the knowledge-retrieval path · **HIGH**

- **Where:** `src/sage_poc/knowledge/postgres_repository.py:78-80, 96`
- **Defect (verified):** `async def _search` calls the plain synchronous `_get_embedding(query)` (CPU inference via `model.encode`) inline on the event loop. The codebase's own pattern for this is `get_embedding_async()` (`memory/embedding.py:35-42`, `run_in_executor` with a docstring saying exactly why), correctly used at the other request-path call sites (`check_user_history.py:59`, `output_gate.py:443`); `skill_select` likewise wraps its semantic match in `asyncio.to_thread` + `wait_for`. This is the one bypass.
- **Failure scenario:** Every `info_request` turn and every mid-protocol `knowledge_lookup` tool call blocks the whole process's event loop for the duration of a CPU encode on Railway — stalling every concurrent request, including crisis-path turns. Directly relevant to the p50-17s latency audit and the unconfirmed concurrency ceiling in the pre-prod blockers.
- **Action (owner-ratified: ship immediately):** Offload the call. Classified as a safety-adjacent performance defect, not a perf nit: it implicates the <3s p95 latency KPI (currently failing at p50 ~17s) and starves crisis-path turns of the event loop.
- **LANDED (2026-08-17):** branch `fix/f3-async-knowledge-embedding`, pushed. Implemented as `await asyncio.to_thread(_get_embedding, query)` rather than replacing the symbol — `_get_embedding` is patched at six existing test sites (`test_knowledge_repository`, `experiment_4_5`), so it stays as the patchable seam. TDD (thread-recorder test RED on the loop-thread assertion, then green); suite failure set byte-identical to master.

### F4 — `embedding_timeout` returned by `skill_select_node` is not a declared `SageState` channel · **MEDIUM**

- **Where:** `src/sage_poc/nodes/skill_select.py:877-885` (the `asyncio.TimeoutError` handler's state return includes `"embedding_timeout": True`); no such key in `src/sage_poc/state.py` (verified, absent on master too)
- **Defect:** LangGraph silently drops any returned key not in the `SageState` TypedDict — the exact bug class `state.py`'s own comments warn about (crisis_tier bug #2, `monitoring_clear_turns`, `precedence_winner`). Only the log line survives. Note the §3a eval harness *already* consumes `out.get("embedding_timeout")` from the node's direct return — which works only because it calls the node function directly, not through the graph; any consumer reading it from graph state gets nothing.
- **Failure scenario:** Anyone wiring `state.get("embedding_timeout")` into the session-audit payload or a degradation gate reads `None` even during an active timeout incident.
- **Action (owner-ratified: fix by declaration AND close the class):** Declare `embedding_timeout: Optional[bool]` as a per-turn channel with a reset in `_build_state` (state-channel-seam convention). This is the third recurrence of the LangGraph dropped-key bug per `state.py`'s own comments, so additionally add a **required** CI check that every key returned by any node function is a declared `SageState` channel — retiring the defect class permanently rather than per-instance.
- **LANDED (2026-08-17):** branch `fix/f4-embedding-timeout-channel`, pushed. All four seam-checklist parts in one commit: declaration, `_build_state` reset, graph-survival + reset tests, and the class closure as an **extension of the existing `scripts/check_state_channels.py`** (already in CI unit-gate) rather than a new check — its blind spot was precise: it enforced only keys both written AND read (`writes ∩ reads`), so a write-only node return was invisible. New rule: any key in a dict literal returned by a `*_node` function must be declared, reader or not; scoped to `*_node` so helper dicts can't false-positive. Blast radius measured before landing: exactly one offender (`embedding_timeout`); the extended gate was run RED on it, then green after declaration. Suite failure set byte-identical to master.
