# Node 2 Finding — Intent Bistability at Reported Confidence 0.9

Date: 2026-07-28. Severity: architecture finding (Node 2 / intent_route), system-wide.
Origin: §1a characterization run-1 vs rerun delta (same user messages, same flags, same
SHA; turn 2 classified `info_request` in run 1 and `new_skill` in the rerun, confidence
0.9 both times). Status: OPEN; linked findings RT-1 (Node 3 never triggered in
benchmarks) and the conformance-matrix validity statement below.

## Decode-parameter check (ran first, per review directive)

Premise correction: the prod intent classifier is NOT Falcon-3B; it is
`openai/gpt-4o-mini` via OpenRouter (the recorded v7 §5.4 Falcon→GPT divergence).

Result: **decode is already greedy.** `_LLM_CONFIGS["classifier"] = (CLASSIFIER_MODEL,
0, 512)` (`llm.py:39-46`), temperature 0, and the fallback classifier likewise. No
top-p override, no sampling. The one-line config fix is ruled out.

## Actual cause (established, two components)

1. **Context stochasticity by architecture.** The intent prompt includes conversation
   history. Turn 1's ASSISTANT reply is generated by the responder at temperature
   0.7 (`llm.py:41`) and differed between runs (both readouts show different turn-1
   copy). Turn 2's classifier therefore conditioned on DIFFERENT input in each run.
   "Identical input" held only at the user-message level, never at the prompt level.
   No decode setting on Node 2 can remove this: the classifier's input embeds a
   temp-0.7 turn by design.
2. **Provider-level nondeterminism (unquantified).** No `seed` is set on the
   ChatOpenAI calls, and OpenRouter may route gpt-4o-mini across providers.
   Temperature-0 OpenAI-family calls are additionally not bit-deterministic under
   batching. Contribution unmeasured; secondary to (1).

## Consequences (severity order, per review)

1. **Confidence is not calibrated.** 0.9 reported on both sides of a flipping
   boundary. Node 3 (`low_confidence_respond`) gates on `intent_confidence < 0.6`;
   if confidence is inflated at genuine decision boundaries, the empathic
   clarification path is unreachable exactly where the architecture needs it.
   **Linked to RT-1:** the Intelligence Evaluation recorded Node 3 as never triggered
   across benchmarks and filed it as untested coverage; inflated boundary confidence
   is a plausible common cause. The two findings should be investigated together.
2. **Single-run characterization is invalid for the whole conformance matrix, not
   just §1a.** Every v5 row is single-run. Rows near intent boundaries are coin flips
   recorded as verdicts, and which rows those are is unknown. The matrix must not be
   cited as settled evidence until distributional re-runs establish per-row
   stability. (Recorded in the parity memory alongside the readback rule. Scoping of
   the distributional re-run was held pending this decode check; the check is now
   done and the cause is architectural, so re-run scoping can proceed.)
3. **Auditability (PDPL).** The audit trail promises reconstruction of every response
   (model version, skill ID, retrieval IDs, cultural rules). With path-level
   nondeterminism, that trace is necessary but not sufficient to reconstruct a
   decision. Required additions to the audit row, cheap now, expensive post-launch:
   classifier decode parameters, a seed if sampling ever lands, and a hash of the
   assembled classifier context (captures the stochastic-history component).

## Remediation directions (not self-approved)

- The `explicit_modality_request` deterministic pre-pass (re-plan) neutralizes
  bistability for the request-handling defect class specifically: all trajectories
  consult the same deterministic flag regardless of which way the classifier flips.
- Confidence calibration study for Node 2 (distributional: N samples per boundary
  fixture, measure flip-rate vs reported confidence) — feeds the RT-1 closure.
- Seed + context-hash audit additions (small PR, joins the readback-coverage PR).
- Responder-history determinism is NOT proposed (temperature 0.7 on therapeutic copy
  is deliberate); the fix is to stop routing deterministic decisions through inputs
  that embed it.
