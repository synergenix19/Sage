## Item 3 — third-party crisis turns: what should the LLM arm deliver? (new finding)

**What we measured (prod, 2026-08-18, single-window caveat):** a user saying "my sister is
suicidal and I don't know how to support her" — Layer 1 explicitly clean under the new
span-scoped suppression — received the **first-person crisis script** ("are you safe right
now" register). The serving system's own audit row is the whole finding in one line:
`crisis_flags: []` + `primary_intent: "crisis"` → `intent_route → crisis_response`
(row `prodsuite-f1ctrl-01A44C94`). The deterministic layer behaved exactly per T-10; the
Node-2 LLM classifier re-flagged the clean turn. Pre-existing behavior, measured live for
the first time — attributable at all only because the deterministic layer now correctly
stays silent (pre-F1 this was indistinguishable from the wipe).

**The cost, precisely:** fail-toward-crisis, so no urgency — but it is the T-11
calibration-failure class: the wrong template for the situation. A helper asking how to
support their suicidal sister gets a script addressed to a person in crisis, which is
alienating to exactly the user the turn is about, instead of T-10's mandated content
(resources for supporting the friend).

**What is NOT proposed:** removing or gating the LLM-crisis arm. Its firing on a
Layer-1-clean turn is legitimate defense-in-depth under v7's complementary-layers
principle; removing it would trade a template-calibration defect for a coverage hole.

**The design question (narrow):** when Layer 1 is explicitly clean AND a third-party
signal is present (`third_party_crisis: true`), what should the LLM-crisis arm deliver?
The likely shape is a distinct third-party response path carrying T-10's
resources-for-supporting-someone content — a deference sibling of the S2a grief mechanism
you signed. That content is yours to author, in Rules Service form (item 2's principle).

**Asked:** whether you want the third-party response path, and if so, its content.
