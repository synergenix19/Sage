## 2. What flipping `active: true` changes mechanically

The rules loader (`src/sage_poc/rules/loader.py`) includes a rule in the evaluated
set only when `rule.active` is true; an `active:false` rule is inert (the engine
never sees it; documented in `tests/test_harm_to_others_node1_backstop.py`, which
was written against the inert-as-shipped state). When active, a pattern match in
`safety_check` (Node 1) emits `crisis_flag: harm_to_others_explicit`, which counts
as an S1 keyword flag, routes tier T2 via the `s1_any` rule in
`src/sage_poc/rules/data/tier_routing/tier_routing.json`, and short-circuits the
graph to `crisis_response`: node_path `["safety_check", "crisis_response"]`. The
2026-07-13 incident probes confirmed the two paths are distinguishable: with the
backstop inactive the same utterance reaches crisis only via
`safety_check -> intent_route` with empty `crisis_flags` (LLM catch); with it
active, `X-Sage-Crisis-Flags: ["harm_to_others_explicit"]` and the deterministic
path. `negation_check` suppresses "I would never hurt him".

There is **no env var** for rule activation. The change is the `"active"` field in
`src/sage_poc/rules/data/safety/crisis_keywords.json` plus the matching sign-off
entry in `superpowers/governance/signed_clinical_fields.json` (the CI pin makes an
unmatched flip unmergeable), shipped as one commit, deployed through
`scripts/deploy_prod.sh` per the runbook, converged behaviorally via
`scripts/deploy_converge.sh` (behavior, never env-SHA, per the standing rule).

## 4. Canary shape: time-boxed, because a traffic split is impossible

**Constraint, stated out loud: prod is a single-instance Railway service. There is
no second instance, no load balancer, no percentage rollout. A traffic-split
canary is impossible.** The canary is therefore TIME-BOXED: the activation serves
100% of traffic for a bounded window with scheduled measurement and an explicit,
pre-committed rollback path.

- **T0 (2026-08-25, deploy owner):** activation deploy + behavioral convergence
  probe (section 5, step 0 cells) + deploy-log entry. If the T0 cells fail their
  direction, roll back the same session; the canary never opens.
- **Window: 72 hours** (2026-08-25 to 2026-08-28), checkpoints at T0+2h, T0+24h,
  T0+72h. Each checkpoint runs the full cell set (section 5) prod-HTTP and reviews
  the organic fires (section 8 query). The +24h and +72h checkpoints are separated
  windows in the sense of the standing window-bounded verification rule, so any
  LLM-adjacent observation needs both; deterministic-tier observations bind at
  first measurement.
- **Close-out (after T0+72h):** verdict recorded (keep active / rollback), sessions
  from probe cells purged (test-user practice per
  `scripts/safety/sf1_phase0_prod_http.py`), record written (section 9).

## 6. Rollback triggers (pre-committed)

- **Any must-NOT-fire cell (N1-N4, N-CTRL) escalates at the deterministic tier in
  the canary window -> flip back + record.** One trigger is sufficient; no
  averaging, no wait-for-the-next-checkpoint.
- **Any fire-direction cell (F1-F4) still missing at the deterministic tier ->
  the backstop is ineffective for its target class.** That is not a rollback-only
  outcome (an ineffective-but-clean surface harms nobody), but it fails the
  canary: investigate the mechanism before any re-try (characterize before build),
  and do not extend the window hoping for drift.
- **Organic must-NOT-fire evidence:** the section 8 review shows a real user
  served the crisis card on a venting-class turn attributable to the new rule ->
  flip back + record. This is the trust-damaging over-escalation the 2026-07-09
  ruling named; it outranks recall wins.

Rollback mechanics: revert the activation commit (one commit per finding, atomic
revert), deploy via the runbook, behavioral readback that F-CTRL still fires
(Group A must survive the rollback) and that the new surface no longer fires.
Record the rollback in the deploy provenance trail and the canary close-out.

## 8. Audit trail: what evidences the backstop firing

`session_audit` rows (writer: `_build_session_audit_row` in
`src/sage_poc/audit.py`) evidence a backstop fire by:

- `crisis_flags` containing `harm_to_others_explicit` (or the new rule's flag id):
  the deterministic-tier signature. LLM-layer catches leave `crisis_flags` empty.
- `node_path` = `["safety_check", "crisis_response"]` (Node-1 short-circuit),
  versus `safety_check -> intent_route -> crisis_response` for an LLM catch.
- `crisis_state`, and when the tiering flag is ON, `crisis_tier` = T2 with
  `tier_rule_id` = `s1_any`.
- At probe time, the `X-Sage-Crisis-Flags` and `X-Sage-Node-Path` headers carry
  the same evidence without DB access.

Canary-window review query: `session_audit` rows in the window where
`crisis_flags` contains the backstop flag id; each fire is read against its
node_path and (metadata-only, no message content is stored) adjudicated as
plausible-target versus FP-suspect. Known limit, on the record from the 2026-07-13
incident sections 7 and 8: the audit trail cannot show what a disarmed or missing
rule failed to catch, and audit writes are swallowed on failure, so absence of
fires is never evidence of absence of the class. Behavioral probe cells, not audit
absence, carry the effectiveness verdict.
